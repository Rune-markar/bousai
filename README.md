# そなえメモ

家庭の防災備蓄を、一般ユーザーが無理なく続けるためのWebアプリMVPです。Notionの「防災備蓄戦略アプリ」資料をもとに、備蓄力の可視化、在庫・期限・不足管理、補充費用、緊急メモ、短い防災知識を一つの操作フローにまとめています。

## 起動

```powershell
npm install
npm run dev
```

## 検証

```powershell
npm run check
```

## MVPに含まれるもの

- 備蓄充足率とカテゴリ別バランス
- 水は1人1日3L、食料は1人1食150g×3食として算出する生存可能日数
- 3・7・14・30日の目標備蓄日数と、目標が長いほど要求段階が上がる総合防災力
- 在庫の追加・編集・削除・消費・補充
- 賞味期限別ロット、補充計画、入出庫履歴
- 賞味期限の近いロットから消費するFEFOローリングストックと自動買い足し候補
- JAN/EAN/UPCバーコードのカメラ・画像読み取りと商品情報の自動入力
- 不足数、補充費用、30日以内の期限警告の自動計算
- 家族人数と在庫の合計量から算出する食料・飲料水の日数（水3L／人日は公的目安、食料重量は1食150g×3食としたアプリ内の簡易比較値）
- 緊急連絡先と集合場所の端末内保存
- JSONバックアップと旧保存データの自動移行
- PWAによる初回表示後のオフライン再起動
- LAN・公開URLを自動候補にするアクセス用QRコードの表示・PNG保存
- 防災知識の読了記録
- 5人の防災ナビゲーター選択、状況別提案、選択肢会話と絆記録
- 命・避難・備蓄・電力・復旧を段階解放する防災力ロードマップ
- 一次・二次避難バッグ、枕元装備、重要書類、代替調理をケース内で点検する視覚的な装備確認
- 保有備蓄の優先度・数量・収納容量から一次／二次避難バッグへ入れる商品と数量を自動選定
- ホームから開く「太陽光 → 蓄電池 → 負荷」の配線図型・停電時電力エコシステム専用ページ
- 負荷ボタンから全機器の個数を一括調整し、変換損失・予備容量を含む必要蓄電池容量へ即時反映
- 計算根拠・安全上の注意・メーカー価格比較を必要なときだけ開ける「？」補足シート
- 計算結果と下部ナビを同時に確認でき、低い端末では主操作部分だけをスクロールするスマートフォン一画面設計
- 在庫と家族情報から作る72時間行動計画、4災害の期間別シミュレーション
- 理由付き消費・廃棄記録、30日傾向、期限・購入先・優先度付き補充計画
- 許可した端末へのキャラクター通知（ブラウザが対応する範囲）
- スマートフォン・タブレット・PC向けレスポンシブUI

商品情報は Open Food Facts API v3 を照会します。Nodeサーバーで配信する場合はアプリ内APIを利用し、GitHub Pagesなどの静的配信ではブラウザから公式APIへフォールバックします。公開データベースにない商品は、読み取ったバーコードを保持したまま手入力できます。商品データの出典は Open Food Facts（ODbL）です。

同一バーコードの商品が端末内にある場合は外部APIより先に再利用し、既存在庫への補充または別賞味期限ロットとしての登録を選択できます。

データはブラウザの `localStorage` に保存されます。備蓄画面から定期的にJSONバックアップを取得してください。クラウド同期、認証、OSのPush通知、災害情報API、生成AIアドバイスは次段階の実装候補です。

食料日数は食料カテゴリの「1単位あたりの食料重量」、水日数は水分カテゴリの「1単位あたりの水量」に在庫数を掛けて合算します。内容量が未登録の品目は安全側に倒して日数へ加算せず、画面上で登録を促します。バーコードの商品情報に `100g` や `6 x 200g` などの内容量がある場合は自動入力します。

装備ケースでは品目をクリックして実物を一つずつ確認します。必須品がすべて揃った後にミッションを完了でき、完了後に必須品を外すと達成も取り消されます。確認状態はほかの端末内データとともにバックアップされます。

### バッグ容量と自動選定

一次避難バッグの標準値は20L、二次避難バッグは40Lです。20Lは[無印良品が防災リュックとして案内する製品](https://www.muji.com/jp/ja/shop/045477/articles/muji-staff/1543715)と[モンベルの20L製品](https://webshop.montbell.jp/goods/disp_fo.php?force=1&product_id=1123821)、40Lは[モンベルの40L製品](https://webshop.montbell.jp/goods/disp.php?product_id=1133364)を基準例にしています。実際のバッグ容量へ切り替えることもできます。

自動選定は、開いている装備ケースから「一時避難（発災直後の移動）」と「2次避難（安全確保後の生活継続）」を識別します。2次避難では一時避難バッグへ先に割り当てた在庫数を除外し、同じ現物を二重に提案しません。各提案には選定理由を表示し、登録在庫から確認できない必需品も別に示します。

形状差や未登録品の余地を残すため、自動選定は容量の85%を実用域として扱います。商品ごとの「1単位あたりの収納容量」をユーザーが入力した場合はその値を最優先します。未入力時は、飲料内容量・商品名や包装表記、それでも判定できない場合はアプリ内の品目別サンプル中央値を順に参照します。内部値は購入判断用の製品仕様ではなく、バッグへ収まるかを事前に試算するための保守的な初期値です。

電力エコシステムは `台数 × 消費W × 使用時間` を基礎に、インバーター効率88%、蓄電池の使用可能率90%、予備20%、太陽光システム効率75%で概算します。メーカー公式価格は画面に記載した確認日時点の参考値であり、医療機器、モーターの起動電力、実際の日照、端子互換性、安全要件は実機仕様と専門家の確認を優先してください。

プロダクション相当の起動は `npm run build` 後に `npm start` を使います。公開先がある場合は `PUBLIC_URL=https://example.com` を設定すると、そのURLがQRコードの優先候補になります。外部APIへの識別情報として、必要に応じて `APP_CONTACT_URL` 環境変数へプロジェクトURLまたは連絡先を設定してください。

サブパスへ静的配信する場合だけ、ビルド時に `APP_BASE=/bousai/` のような末尾スラッシュ付きの公開パスを指定します。ローカルの `npm start` は既定でルート配信されます。
