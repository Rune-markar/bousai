# 停電時電力エコシステム専用ページ 設計仕様

## 目的

防災力ロードマップの途中に長く埋め込まれている蓄電池・太陽光の電力エコシステムを専用ページへ移し、スマートフォンでは下部ナビゲーションを含む一画面の中で主要な確認と変更を完結させる。

## 導線

- ホーム画面に「停電時の電力を設計」カードを追加する。
- カードから `power` ページへ遷移する。
- 防災力ロードマップから既存の長い `PowerEcosystem` セクションを削除する。
- メインナビゲーションには項目を追加せず、既存の5項目とスマートフォンでの押しやすさを維持する。
- 専用ページからホームへ戻れる明示的な戻る操作を用意する。

## 専用ページの構成

### 共通領域

- ページ見出し、戻る操作、計算条件、3タブ、選択中タブの内容、固定結果バーで構成する。
- タブは「機器」「蓄電池」「太陽光」の順とする。
- 日数と有効日照時間は一画面内で変更でき、結果へ即時反映する。
- 固定結果バーには「必要な蓄電池容量」「必要な太陽光パネル出力」「電源とパネルの概算費用」を表示する。
- 既存の `state.powerPlan` と `calculatePowerSystem` を利用し、保存済み設定と計算結果の互換性を維持する。

### 機器タブ

- 8種類の機器を横方向に送れるカード列で表示する。
- 各カード内の減算・加算ボタンで台数を0〜20台の範囲で変更する。
- 選択中の機器数、1日使用量、同時最大出力を簡潔に表示する。
- 簡易・詳細計算の切り替えを残す。詳細計算で必要な想定W、実測W、使用時間は補助シートで編集し、主画面を圧迫しない。

### 蓄電池タブ

- 必要な表示容量と推奨AC出力を主情報として大きく表示する。
- 容量・出力・概算本体価格の意味を、それぞれ対応するヘルプから確認できるようにする。
- メーカー公式価格比較は補助シートへ移す。

### 太陽光タブ

- 必要な定格出力と、指定した有効日照時間で1日分を回復する想定を主情報として表示する。
- 発電効率、天候・角度による差、概算パネル価格、メーカー公式価格比較は補助シートへ移す。

## 補足情報の表示

- 補足があるラベルには、押下可能な丸い「？」アイコンを配置する。
- アイコンは内容を特定できる `aria-label` を持つ。
- 押下すると画面下から補助シートを開く。
- 補助シートは閉じるボタン、背景押下、Escapeキーで閉じられる。
- 開いている間は `role="dialog"`、`aria-modal="true"`、見出しとの関連付けを提供する。
- 変換損失、使用可能容量と予備、太陽光損失、医療機器、モーター起動電力、価格確認日、見積もり上の注意を削除せず、関連する補助シートへ整理する。

## レスポンシブ動作

- 幅390pxを主要なスマートフォン検証基準とする。
- スマートフォンではページコンテナを `100dvh` 基準とし、上部ヘッダーと下部ナビゲーションを除いた残りへ専用ページを収める。
- ドキュメント全体の縦スクロールと横スクロールを発生させない。
- 機器カード列だけ横スクロールを許可し、スナップ位置を設ける。
- 高さが不足する端末では選択中タブの主操作領域だけ内部縦スクロールを許可し、固定結果バーと下部ナビゲーションを維持する。
- PCでは同じ情報と操作を広いレイアウトへ展開し、保存形式や操作モデルを分岐させない。

## 状態とエラー処理

- 台数、日数、日照時間、簡易・詳細モードは既存の正規化処理を通して保存する。
- 不正値は現在の `normalizePowerPlan` の範囲制約へ委ねる。
- 機器が0台の場合は、容量・パネル・費用を0として表示し、機器追加を促す空状態を示す。
- 外部のメーカー公式ページは新しいタブで開き、アプリ内計算はリンク到達性に依存させない。

## アクセシビリティ

- タブは選択状態を支援技術へ伝え、キーボードで操作できる。
- 加減算ボタンは対象機器と操作内容が分かる名前を持つ。
- 横スクロールを必須操作にせず、フォーカス移動でもすべての機器へ到達できる。
- 色だけで選択状態や重要度を伝えない。
- タップ対象はスマートフォンで押しやすい寸法を確保する。

## 検証

- ホームカードから専用ページへ遷移できることをコンポーネントテストで確認する。
- 防災力ページに旧電力セクションが存在しないことを確認する。
- 3タブ切り替え、台数変更、日数変更、日照変更、保存状態、計算結果をテストする。
- 各「？」が対応する補助シートを開き、閉じるボタンとEscapeキーで閉じることをテストする。
- 既存の `power.test.js` を維持し、計算ロジックの回帰を確認する。
- `npm run check` で全テストとプロダクションビルドを確認する。
- 実ブラウザの390px幅で、`document.documentElement.scrollWidth === document.documentElement.clientWidth` とページ全体の縦スクロール不発生を確認する。
- 低いビューポートでは主操作領域だけが内部スクロールすること、PC表示に崩れがないことを確認する。

## 対象外

- 計算式、価格ベンチマーク、保存データ形式の変更。
- 新しいメーカーや機器種類の追加。
- 下部ナビゲーションへの「電力」項目追加。
- 外部API、クラウド同期、購入機能の追加。
